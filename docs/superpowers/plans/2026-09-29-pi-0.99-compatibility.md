# pi 0.99 compatibility check — mx-pi-agents & mx-pi-context-stats

Date: 2026-09-29
Target: `@earendil-works/pi-coding-agent` / `@earendil-works/pi-tui` **0.99.1** (latest)
Previous pin: dev deps `^0.81.1`, peer deps `>=0.80.0`

## Verdict

**Compatible.** No production logic change was required for the 0.99 runtime.
Two test-suite fixes were needed, and the dev dependencies are now bumped to
0.99.1. `mx_pi_agent` also gained the new 0.99 tool metadata.

## Issues found and fixed

1. **`ExtensionToolContext` gained required members.** 0.99 added `tools` and
   `executeTool` to the tool-callback context, so a bare `ExtensionContext` is no
   longer assignable where a tool `execute` context is expected. Fixed in
   `packages/mx-pi-agents/src/runners/confine.test.ts` by typing the fake context
   as `ExtensionToolContext`. (Type-check only; no runtime effect.)

2. **Child session creation hit the network (the real find).** A child
   `createAgentSession` builds its own `ModelRuntime` when the runner is not given
   one. `ModelRuntime.refresh()` defaults `allowNetwork` to `modelNetworkEnabled`,
   so with a fresh temp `agentDir` and no explicit `allowModelNetwork:false` the
   child refreshes the **remote model catalog**. On a cold, parallel test run this
   surfaced as a hard **20 s timeout** in `in-process.test.ts` — the suite labeled
   "no model call" was in fact making a network call and depending on the
   machine's real `~/.pi` model state. Fixed by pinning the whole test run offline
   (`vitest.config.ts` → `test.env: { PI_OFFLINE: "1" }`), which makes tests
   hermetic. A file-scoped `testTimeout: 20_000` on the real-`AgentSession` suite
   covers cold lazy-compile under parallel transform load.
   - **Production note (not yet changed):** `index.ts` constructs
     `createInProcessRunner({ agentDir })` without `deps.modelRuntime`, so every
     child creates and refreshes its own runtime. It is correct but can add
     latency when the catalog store is cold. Passing the parent runtime would
     avoid the re-init; left as a follow-up because the extension API does not
     expose a `ModelRuntime` directly.

## Breaking changes reviewed (0.82 → 0.99) and why they do not apply

- **0.83** — TypeBox 1.3.7 removed `Type.Base`, `Type.Awaited`, `Type.Promise`,
  `Value.Mutate`, … Extensions use only `Type.Object/Optional/String/Array`.
- **0.84** — `message_update` dropped cumulative `message` /
  `assistantMessageEvent.partial`. `mx-pi-context-stats` reads only
  `event.assistantMessageEvent.type`.
- **0.84** — `ModelRegistry`/`ModelRuntime` auth projection changes;
  `ctx.modelRegistry.find/getAll` still exist on `ExtensionContext`.
- **0.86** — JSON tool values, `user_bash` fail-closed, provider `Context` →
  `TranscriptContext`. Tool `details` stay plain JSON; `user_bash` and custom
  providers are unused.
- **0.87** — `TurnEndEvent` gained boundary fields and `AgentBeforeSettleEvent`
  was added; `turn_end` handlers read only `event.message`, which is unchanged.
  No session replacement or `shouldStopAfterTurn` usage.
- **0.99** — new tool APIs (`exposure`, `namespace`, `annotations`, `outputSchema`,
  `ctx.executeTool`), `registerVirtualModel`, `registerMcpServer`, theme
  `style()/colors/appearance`. Additive; `exposure` defaults to `"direct"`, so
  `mx_pi_agent` stays model-visible.
- **0.99** — `--no-extensions` now also disables built-in extensions, which
  strengthens the subprocess runner's existing child isolation.

## Changes applied

- Dev deps bumped in both packages: `@earendil-works/pi-coding-agent` and
  `@earendil-works/pi-tui` → `^0.99.1`; `typebox` → `^1.3.27`. Peer ranges stay
  `>=0.80.0` per repo convention. `package-lock.json` refreshed.
- `mx_pi_agent` now registers `namespace` and `annotations`
  (`readOnlyHint: false`, `destructiveHint: true`, `idempotentHint: false`,
  `openWorldHint: true`) so permission extensions can gate delegated runs.
- `confine.test.ts` fake context typed as `ExtensionToolContext`.
- `vitest.config.ts` runs offline (`PI_OFFLINE=1`); the real-`AgentSession` suite
  gets a 20 s timeout.
- `packages/mx-pi-agents/CHANGELOG.md` records the above under `[Unreleased]`.

### Not changed, deliberately

- **Theme rendering.** The widget/progress renderers use `theme.fg(<role>, text)`
  with semantic roles (`muted`, `dim`, `accent`, `warning`, …). 0.99's
  `theme.colors` / `theme.style()` expose raw colors; switching would trade
  semantic, theme-agnostic roles for palette entries and regress readability
  across themes. `theme.fg` remains supported.

## Follow-ups

- Added `packages/mx-pi-context-stats/CHANGELOG.md` with an `[Unreleased]`
  section (it was the only package without one), so the release script promotes
  its changes too.
- Consider passing the parent `ModelRuntime` into the in-process runner to avoid a
  per-child catalog init once the extension API exposes it.
- The `>=0.80.0` peer range spans several breaking releases. 0.81.1 and 0.99.1 are
  verified; intermediate versions are not. Document the tested range if that
  matters to consumers.
